## Возможности

- **TOTP** - совместим с Google Authenticator, Authy, Aegis и любыми приложениями по RFC 6238; допускается смещение на ±1 шаг (30 с); принятый код нельзя использовать повторно.
- **Email** - одноразовый 6-значный код на подтвержденный адрес через почту MODX (SMTP), с паузой между повторными отправками.
- **Telegram** - привязка по QR-коду / deep-link с подтверждением кнопкой в боте; вход по 6-значному коду из бота **или** одной кнопкой «Разрешить вход» (или «Отклонить»).
- **WebAuthn / FIDO2 / Passkeys** - Touch ID, Face ID, Windows Hello, аппаратные ключи; алгоритмы ES256, RS256, Ed25519; детект клонирования по счетчику подписей.
- **Менеджер и фронтенд** - независимое включение 2FA для админки MODX и для пользователей сайта (совместим с Login).
- **Защита от перебора** - 3 неверных кода блокируют вход на 15 минут (настраивается); состояние хранится в БД и переживает перезапуск; лимит действует и при настройке нового метода.
- **Шифрование секретов** - TOTP-секреты хранятся только в зашифрованном виде (libsodium XChaCha20-Poly1305); ключ лежит вне компонента.
- **Усиление сессий** - регенерация ID сессии после двутапного входа; список активных сессий за 30 дней и отзыв по одной; принудительный перевыпуск 2FA по возрасту сессии.
- **QR без посредников** - QR-коды создаются локально в браузере встроенной библиотекой (MIT), одноразовые токены не передаются на внешние сервисы.
- **CSRF и same-origin** - токены на всех формах подтверждения, POST + проверка Origin/Referer для операций, меняющих состояние.
- **Диагностика безопасности** - прямо на главной странице компонента в менеджере (ключ, sodium, HTTPS, cookie-флаги, CSP, статус плагинов).

## Требования

- MODX Revolution **3.x**
- PHP **8.1+** с расширением **sodium** (`ext-sodium` входит в PHP по умолчанию с 7.2)
- **HTTPS** для сайта; обязателен для Telegram-вебхука и WebAuthn (WebAuthn работает по HTTP только на `localhost`)
- Для маршрутов по умолчанию `/2fa` и `/2fa-web` - включенные дружественные URL (иначе используются прямые адреса, см. [Устранение неполадок](#устранение-неполадок))

## Установка

### Из транспортного пакета

1. Возьмите `modtwoauth-1.0.0-pl.transport.zip` из [релизов](https://github.com/vitos88/ModTwoAuth/releases).
2. В менеджере откройте **Приложения → Управление пакетами**, загрузите пакет и установите.
3. Установщик создаст таблицы БД, сгенерирует ключ шифрования `core/config/modtwoauth.key` (права 0600) и автоматически зашифрует ранее сохраненные открытые TOTP-секреты.
4. Проверьте страницу компонента (**Приложения → modtwoauth**) - там же выводится диагностика безопасности.

### Сборка из исходников

```bash
php _build/build.php
```

После сборки transport-пакет появится в `core/packages/`. Чтобы скачать zip из браузера на dev-сервере, откройте `http://dev.site/_build/build.php?download=1` (потребуется авторизованный менеджер с правом sudo).

## Быстрый старт

### 2FA для менеджеров

1. В **Системные настройки → ModTwoAuth** включите `modtwoauth_enable_2fa`.
2. Каждый менеджер настраивает метод для себя: **Пользователи → редактирование своей учетной записи → вкладка «🔐 2FA»** - сканирование QR, подтверждение email-кода, привязка Telegram или регистрация Passkey, затем переключатель «Включить 2FA».
3. Со следующего входа MODX запросит второй фактор после пароля. Менеджер всегда использует штатный шаблон страницы подтверждения (чанк `modtwoauthVerifyTpl`); URL меняется настройкой `modtwoauth_verify_url` (по умолчанию `/2fa`).

### 2FA для пользователей сайта (фронтенд)

1. Включите `modtwoauth_frontend_enable_2fa` (по умолчанию включено).
2. Разместите сниппеты на странице, доступной авторизованным пользователям (например, в личном кабинете):

```html
[[!ModTwoAuthFrontend]]
[[!ModTwoAuthSessions]]
```

3. Пользователи сами настраивают методы, включают 2FA (после входа) и видят список активных сессий за 30 дней; любую другую сессию можно завершить - она будет отклонена при следующем запросе. Отключение 2FA требует ввода текущего пароля.
4. Страницу подтверждения на фронтенде можно оформить своим чанком - укажите его ID в `modtwoauth_verify_chunk_id`. Пустое или неверное значение откатывается к штатному `modtwoauthVerifyTpl`; на админку эта настройка не влияет.

## Настройка методов

### TOTP (приложение-аутентификатор)

1. В профиле (вкладка 2FA) выберите метод TOTP и нажмите «Сгенерировать QR».
2. Отсканируйте QR в приложении или введите секрет вручную.
3. Введите текущий 6-значный код для подтверждения. После 3 неверных попыток секрет аннулируется - потребуется новый QR.

Секрет 160-бит, в БД хранится только в зашифрованном виде; повторное использование принятого кода невозможно (запоминается timestep по RFC 6238 §5.2).

### Email

1. Выберите метод Email и укажите адрес (на фронте код уходит на email профиля пользователя).
2. Введите 6-значный код из письма. Код живет `modtwoauth_code_lifetime` секунд (по умолчанию 300), повторная отправка - не чаще раза в `modtwoauth_resend_cooldown` секунд (60).

### Telegram

1. Создайте бота через [@BotFather](https://t.me/BotFather) и укажите токен в `modtwoauth_telegram_bot_token`.
2. Сайт должен быть доступен из интернета (не localhost) по HTTPS: вебхук регистрируется пакетом автоматически при создании запроса на привязку/вход. Секрет вебхука выводится из токена бота и проверяется на каждом запросе.
3. Пользователь сканирует QR (или переходит по deep-link), нажимает **Start**, затем в боте - **Подтвердить подключение**. Запрос одноразовый, действует 5 минут; в БД хранятся только хеши токенов.
4. При входе бот присылает 6-значный код и кнопки **Разрешить вход** / **Отклонить**. Подтвердить может только чат, привязанный к аккаунту.

### WebAuthn / FIDO2 / Passkeys

- RP ID определяется по хосту менеджера (`manager_url`) для менеджера и по `site_url` для фронтенда; при необходимости задайте `modtwoauth_webauthn_rp_id` (можно указать как «example.com», так и полный URL).
- Тип аттестации - `none` (проверка цепочки аттестации вендора не выполняется - осознанно).
- `residentKey: preferred`, `userVerification: preferred` - passkeys работают без списка credentials.
- Счетчик подписей аутентификатора проверяется (детект клонированных ключей); для аутентификаторов без счетчика проверка пропускается.
- Поддерживаются подписи ES256 (включая корректную обработку DER и raw R‖S) и RS256 через OpenSSL, Ed25519 через sodium.
- Неверные попытки входят в общий лимит `modtwoauth_max_attempts` / `modtwoauth_lock_minutes`.

## Сниппеты фронтенда

### `[[!ModTwoAuthFrontend]]`

Личный кабинет 2FA: выбор и настройка методов, включение/отключение (с подтверждением паролем).

| Параметр | По умолчанию | Описание |
|---|---|---|
| `&tpl` | `modtwoauthFrontendSettingsTpl` | ID чанка-шаблона (можно не указывать) |
| `&methods` | все | Список методов через запятую: `totp,email,telegram,webauthn` (можно не указывать) |

### `[[!ModTwoAuthSessions]]`

Список активных сессий пользователя (за 30 дней) с кнопкой завершения.

| Параметр | По умолчанию | Описание |
|---|---|---|
| `&tpl` | `modtwoauthSessionsTpl` | ID чанка-шаблона (можно не указывать) |
| `&showCurrent` | `1` | `0` - скрыть текущую сессию из списка |

Оба сниппета доступны только авторизованным в любом веб-контексте пользователям.

## Системные настройки

| Настройка | По умолчанию | Описание |
|---|---|---|
| `modtwoauth_enable_2fa` | Нет | Включить 2FA в админке |
| `modtwoauth_frontend_enable_2fa` | Да | Включить 2FA на фронтенде |
| `modtwoauth_code_lifetime` | 300 | Время жизни email/telegram-кода и pending-окна входа, сек. (мин. 30) |
| `modtwoauth_max_attempts` | 3 | Неверных кодов до блокировки |
| `modtwoauth_lock_minutes` | 15 | Длительность блокировки, мин. |
| `modtwoauth_resend_cooldown` | 60 | Пауза между повторными отправками email-кода, сек. (мин. 15) |
| `modtwoauth_session_max_age` | 86400 | Макс. время подтвержденной 2FA-сессии, сек.; `0` - без ограничения. Применяется только к сессиям, прошедшим второй фактор; устаревшая сессия принудительно завершается |
| `modtwoauth_verify_url` | `/2fa` | URL страницы подтверждения в manager. Путь от корня сайта (требуются дружественные URL); при выключенных ЧПУ со значением по умолчанию используется прямой адрес `/assets/components/modtwoauth/verify.php` |
| `modtwoauth_web_verify_url` | `/2fa-web` | URL страницы подтверждения на фронтенде (те же правила) |
| `modtwoauth_verify_chunk_id` | 0 | ID своего чанка страницы подтверждения **на фронтенде** (0 - штатный; manager не затрагивается) |
| `modtwoauth_telegram_bot_token` | - | Токен Telegram Bot API |
| `modtwoauth_email_from_name` | - | Имя отправителя; пусто - берется `site_name` |
| `modtwoauth_email_from_address` | - | Адрес отправителя; пусто - берется `emailsender`. Адрес проходит валидацию |
| `modtwoauth_key_path` | - | Свой путь к ключу шифрования (относительный путь считается от `MODX_BASE_PATH`) |
| `modtwoauth_csp_report_only` | Да | Отправлять CSP в режиме Report-Only (не блокирует) |
| `modtwoauth_csp_policy` | `default-src 'self'; base-uri 'self'; object-src 'none'; frame-ancestors 'self'; form-action 'self'; upgrade-insecure-requests` | Значение политики CSP |
| `modtwoauth_webauthn_rp_id` | - | Явный WebAuthn RP ID (хост или URL) |

Приоритет источника ключа: переменная окружения `MODTWOAUTH_KEY_PATH` → `modtwoauth_key_path` → `core/config/modtwoauth.key`.

## Письма с кодами

Тема и HTML-текст письма настраиваются в словарях `modtwoauth_email_subject` и `modtwoauth_email_body` (тема `modtwoauth:default`). Доступные плейсхолдеры: `[[+code]]` - код, `[[+minutes]]` - срок действия в минутах.

## Ключ шифрования

Ключ создается установщиком в `core/config/modtwoauth.key` (0600). **Сделайте его бэкап**: при потере ключа зашифрованные TOTP-секреты не восстановить - пользователям потребуется делать перевыпуск.

Вынос ключа за document root на новой установке (пути и владельца адаптируйте под свой сервер):

```bash
install -d -m 700 /var/www/site/modtwoauth
umask 077
php -r 'echo base64_encode(random_bytes(SODIUM_CRYPTO_AEAD_XCHACHA20POLY1305_IETF_KEYBYTES)), PHP_EOL;' \
  > /var/www/site/modtwoauth/modtwoauth.key
chmod 600 /var/www/site/modtwoauth/modtwoauth.key
```

Затем укажите полный путь в настройках `modtwoauth_key_path`; пользователь PHP-FPM должен иметь право читать файл. Если TOTP уже настроен, **не создавайте новый ключ**: сначала перенесите существующий `core/config/modtwoauth.key` в новое место и только потом меняйте настройку.

## Сессии и устройства

- Записи о сессиях хранятся в таблице `twoauth_sessions` (IP, User-Agent, время создания и активности). Активность обновляется не чаще раза в минуту.
- Список сессий в админке - во вкладке «2FA» профиля; список веб-версии - сниппетом `ModTwoAuthSessions`. Отображаются сессии активные за последние 30 дней; токены в списки не выводятся.
- Отзыв чужой сессии: удаляется запись, и при следующем запросе плагин (`OnManagerPageInit` / `OnWebPageInit`) завершит эту сессию. Текущую сессию из интерфейса отозвать нельзя.
- `modtwoauth_session_max_age` принудительно завершает подтвержденную 2FA-сессию старше указанного возраста - пользователю придется войти заново.

## Безопасность

Механизмы, примененные в компоненте:

- второй фактор передается **только** через штатные страницы подтверждения; обойти его запросом с внешним флагом невозможно - таких флагов нет;
- при блокировке вход **отклоняется**, а не «проваливается» в проверку пароля;
- принятый TOTP-код не принимается повторно; email/telegram-коды хранятся только как bcrypt-хеши;
- все страницы подтверждения защищены CSRF-токенами; коннектор и процессоры требуют POST и сверяют Origin/Referer; список действий коннектора - allowlist;
- при включенной 2FA нельзя «тихо» перезаписать метод прямым вызовом процессора - сначала отключение через профиль;
- ID сессии регенерируется после успешного второго фактора (менеджер, фронтенд, Telegram, WebAuthn);
- редиректы после 2FA проверяются по схеме, хосту и порту сайта (защита от open redirect);
- Telegram-вебхук отвергает запросы без корректного секрета; в БД только хеши одноразовых токенов; подтвердить вход может только привязанный чат;
- сообщения сервера экранируются перед вставкой в DOM; токены сессий в UI не выводятся; детали исключений пишутся только в журнал MODX;
- TOTP-секреты шифруются libsodium XChaCha20-Poly1305 с ключом вне дерева компонента.

Чеклист сервера после установки:

1. HTTPS на менеджере и сайте.
2. `session.cookie_secure=1`, `session.cookie_httponly=1`, подходящий `session.cookie_samesite` в PHP.
3. Ключ шифрования перенесен за document root (или проверено `0600`), есть бэкап.
4. Изучите отчеты CSP Report-Only в консоли браузера перед включением блокирующей политики (`modtwoauth_csp_report_only=Нет`).
5. Диагностика на главной странице компонента должна показывать все пункты зелеными.

## Устранение неполадок

**Вход не запрашивает второй фактор.** У пользователя метод не включен или не верифицирован (переключатель «Включить 2FA»), либо выключена `modtwoauth_enable_2fa` (менеджер) / `modtwoauth_frontend_enable_2fa` (фронтенд). 2FA действует только для пользователей с настроенным и включенным методом.

**Дружественные URL выключены - `/2fa` не открывается.** Используются прямые адреса `/assets/components/modtwoauth/verify.php` (менеджер) и `/assets/components/modtwoauth/web-verify.php` (фронтенд). Свой URL маршрута требует FURL, иначе укажите прямой путь.

**«3 неверных кода» - аккаунт заблокирован.** Подождите `modtwoauth_lock_minutes` (по умолчанию 15) либо администратор временно отключает 2FA в профиле пользователя и включает заново после входа.

**Telegram: бот не отвечает / вебхук не ставится.** Сайт должен быть доступен публично по HTTPS, токен - валидный. Ошибки Telegram API пишутся в журнал ошибок MODX.

**WebAuthn: «Безопасный контекст» / ошибка создания ключа.** WebAuthn требует HTTPS (исключение - `localhost`). RP ID должен совпадать с хостом страницы: для нестандартных поддоменов задайте `modtwoauth_webauthn_rp_id`.

**Не настраивается TOTP - ошибка шифрования.** Не установлено/не подключено расширение sodium, или недоступен файл ключа. Проверьте пункт «sodium» в диагностике компонента.

**Смена `modtwoauth_key_path` при уже работающем TOTP.** Сначала перенесите существующий `core/config/modtwoauth.key` в новое место, затем измените настройку. При указании несуществующего пути компонент попытается скопировать штатный ключ автоматически, но лучше сделать это вручную.

**Потерян ключ шифрования.** Зашифрованные TOTP-секреты не восстановимы: пользователям нужно отключить и заново настроить TOTP (секреты email/telegram/webauthn не страдают).

## История изменений

### 1.0.0-pl

Первый публичный релиз.

**Методы аутентификации:** TOTP (RFC 6238, окно ±1), Email-коды, Telegram (QR/deep-link привязка, вход кодом или кнопкой в боте), WebAuthn/FIDO2/Passkeys (ES256/RS256/Ed25519) - для менеджера и фронтенда.

**Безопасность:**

- Защита от повторного использования TOTP-кода (timestep последнего принятого кода в БД).
- Telegram-вебхук отвергает все запросы без секрета; секрет выводится из токена бота; в БД только хеши одноразовых токенов; подтверждение входа привязано к чату и сессии.
- Ограничена частота отправки email-кодов (`modtwoauth_resend_cooldown`); общий лимит неверных попыток с блокировкой, персистентной в БД; при настройке методов - свои лимиты попыток.
- Регенерация ID сессии после 2FA во всех потоках; списки сессий и отзыв по одной; `modtwoauth_session_max_age` принудительно завершает устаревшие 2FA-сессии.
- TOTP-секреты шифруются libsodium XChaCha20-Poly1305; ключ можно выносится за пределы компонента (системная настройка); автоматическая миграция открытых секретов при установке.
- CSRF-токены на всех формах подтверждения; опциональный CSP Report-Only; диагностика безопасности в панели.
